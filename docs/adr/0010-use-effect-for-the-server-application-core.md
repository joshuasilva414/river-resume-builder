# Use Effect for the server application core

Resume Builder will pin one exact Effect 4 release-candidate version across all Effect packages and prove it with a Phase 0 compatibility spike before foundation implementation. The spike must cover TanStack Start on Cloudflare Workers, Effect Schema, Drizzle with D1, Better Auth, R2 bindings, and Workflow-step execution. Moving to Effect 4 stable requires the same checks to pass. Effect Schema is the canonical runtime schema system; Zod is permitted only inside an isolated third-party adapter that requires it.

Effect owns server application services, typed failures, Layers, configuration, resource scopes, bounded concurrency, and short retry or timeout policies. TanStack Start server functions and routes, MCP handlers, and Cloudflare Workflow steps are composition boundaries that execute Effect programs. Drizzle remains the only D1 query layer, TanStack Query and Form remain the browser data and form tools, and Cloudflare Workflows remains the durable orchestration layer. Resume Builder will not adopt Effect HTTP, Effect SQL, Effect Workflow, or Effect client-state abstractions in V1 because they would duplicate accepted platform responsibilities or add avoidable Cloudflare compatibility risk.
