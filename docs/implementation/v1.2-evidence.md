# River v1.2 evidence and source implementation

This work implements the simplified evidence and extraction portion of the approved [v1.2 plan](v1.2-plan.md). It does not claim staging or browser acceptance; the release owner records those results separately.

## Behavior

- Evidence has text, keywords, optional sources, and a type: Skill, Achievement, Experience, Education, Credential, or Other. One save commits text, type, keywords, and source links together. Saved evidence is usable immediately.
- Existing material revisions, exact citations, contexts, decisions, and saved document records remain readable. Current records without a recognized type migrate to Other. Historical review state does not filter active evidence or block new exports.
- Evidence and sources have Delete and Restore actions without a required reason. Source originals and immutable extraction results remain stored. Source deletion invalidates pending extraction acceptance, including after restoration, so users must review fresh results.
- A source captures the selected personal model at intake. Document processing queues evidence extraction durably after successful publication; it continues after the page closes. Retries retain the original request identity and cannot silently change models when account defaults change.
- The v3 extraction contract considers all bounded passage groups. It includes explicit skills throughout the document and requests action-oriented résumé phrasing with an implied first-person subject. Skill evidence contains skill names. The old twenty-item cutoff is removed. The explicit result bound is 1,000 items, and complete-input limits are enforced without slicing source text or results.
- Generation is bounded to 60 seconds per provider call and 10 minutes for a source operation. Cancellation is checked between groups, and terminal operation guards reject late publication.
- Extracted items are editable before one Add selected or Add all action. The count covers the complete result set across pages. Every observed item identity and digest is validated in one transaction. The whole batch fails on a stale input, and the same successful command can be retried without duplicating evidence. The atomic guard uses a single JSON parameter to stay below D1's variable limit for larger batches.
- New export reports use `river-evidence-export-v2` or `river-source-evidence-export-v2`. Missing sources and legacy verification state do not create issues. Changed and trashed references are information and need no acknowledgment. Document completeness, renderer/template identity, and passing document validation remain required. Stored historical exports keep their original report and policy.
- REST and MCP expose typed evidence, optional sources, and trash. `POST /api/v1/evidence/import` accepts reviewed extraction batches. `PATCH /api/v1/sources/:id` changes trash state. MCP no longer advertises review commands or verification permissions. Old verification calls return an explicit v1.2 migration error, and previously stored credentials remain readable.

## Design implementation

Paper was inspected and changed by the dedicated design worker before UI implementation. See [v1.2 Paper handoff](v1.2-paper.md).

- `BF4-0`, `BFI-0`, `BFR-0`, `BGV-0`: extraction review, all-result actions, editable rows, pagination.
- `BH0-0`, `BH7-0`, `BH8-0`: direct evidence editor and source processing/cancellation/failure/success states.
- Existing typography, theme tokens, shell, controls, and responsive stacking are retained. Ordinary evidence views no longer show verification, provenance, rationale, or technical identifiers. Library evidence selectors follow the same model.

Implementation status: implemented; focused automated checks passed as recorded below. Browser inspection and hosted acceptance remain release-level work.

## Files and compatibility

`0035_v1_2_evidence.sql` normalizes current evidence types and adds source trash and saved model selection fields. It does not rewrite historical material, review decisions, or exported reports.

`EvidenceMaterialInput.sourceIds` adds optional source links without requiring exact citation selection. Existing `citations` and `contexts` remain supported. `EvidenceMetadata.type` remains optional for old records and clients; current writes normalize it to Other. Evidence text retains the existing wire name `assertion`, and keywords retain `metadata.tags` for compatibility.

The legacy review writer and clarification reader remain internal compatibility paths. New public verification is retired, and accepting extraction results no longer creates clarification workflows.
