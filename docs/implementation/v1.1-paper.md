## Visual implementation values

Values below were obtained through Paper tokens and computed styles, not estimated from screenshots. Use the application's existing equivalents.

- Paper `#FFFFFF`, ink `#111318`, graphite `#5B6270`, rule `#D9DDE3`, editor `#1E5EFF`, approved `#16794A`.
- Preserve Newsreader headings, Instrument Sans content/controls, and IBM Plex Mono for design annotations or advanced execution identities. The normal UI does not expose design annotations.
- Main page title: Newsreader 40px / 44px, weight 600, tracking -0.025em. Section/editor heading: 28px / 32px. Body: 15–16px / 23–24px; controls: 14px / 20–22px; supporting text: 13px / 20px.
- Settings workspace `AOD-0`: 40px vertical padding, 80px horizontal padding, 28px gap. Fit into the existing application shell; use the available workspace width rather than reproducing a second shell.
- Settings columns `AOI-0`: 48px gap, flexible connection list and 352px default panel. Default panel: 24px padding, 18px gap, 8px radius, 1px rule border.
- Provider rows: 24px vertical padding, 40px fixed leading identity slot, flexible description, 102px fixed trailing action slot. Inputs/buttons are at least 44px tall with 4px radius.
- Shared AI components `AR6-0` / `ARG-0`: 24px padding, 16px gap, 8px radius, 1px rule border. Connection editor `AQJ-0`: 480px preferred width, 28px padding, 20px gap.
- Single editor `AUH-0`: 24px padding, 20px gap, 8px radius, 1px rule border. State boards show consecutive views next to each other; the application renders one view at a time.
- Use fit-content heights. Preserve generous reading space without fixed-height empty cards. On narrow screens, stack settings columns and action choices; keep controls full width and retain 44px hit areas.
- Mobile examples are 390px wide, with 20px content padding, 24px gaps, 32px / 36px Newsreader headings, and 48px primary controls. Native status bars on these presentation boards are mockup chrome, not application content.
- Dark surfaces use the existing `--color-dark-*` tokens: ground `#0B0D12`, surface `#141821`, text `#F4F6FA`, muted `#A8AFBD`, rule `#303746`, editor `#5B8CFF`, approved `#45C58A`. Set text colors explicitly where needed.

## Behavior handoff

- One saved connection for each of OpenAI, Anthropic, Google Gemini, and OpenRouter. Connect supports test/save and cancel. Manage supports test, replace, and remove. Only masked key metadata is displayed.
- Default model and action override use provider catalogs. Model names in Paper are illustrative, never hardcoded defaults. Saving or starting an action requires a selected available model.
- Compact AI controls identify provider/model and summarize sent material. Change expands the selector in place. A per-action choice does not change the account default. No connection offers Settings and manual editing. ATS scoring's separate funding path is explained in Settings.
- Onboarding offers import or manual entry, an optional AI connection step, Skip setup, and a resumable checklist. Checklist completion comes from saved account work.
- Seven starters contain empty fields and suggested headings, with no fictional content. Contact exposes ordinary contact fields directly. Saving creates the required reusable structure together.
- Library child creation, selection, citation inspection, and unsaved-exit confirmation replace the single editor view. Back restores parent fields, validation, and selections. Cancel does not attach the unfinished child. Escape/focus return must follow the current view rather than leaving stacked dialogs.
- Production review retains actual before/after wording, relevant source excerpts, current evidence changes, PDF comparison, and actionable warnings. Lists use compact titles and summaries; selecting an item opens its review. Original uploads remain available through Sources. Do not return prompts, complete-input dumps, graphs, hashes, offsets, raw JSON, or LaTeX in ordinary page payloads.
- PDF is the primary export; plain text is secondary. Download controls retain the underlying review and artifact-availability gates. An available prior PDF remains visible during refresh, and pending changes cannot be represented as an approved export.
- Advanced tools are off by default. Enabling adds a separate destination; it does not restore technical dropdowns to normal screens. Document source, template code, execution details, `.tex` and JSON exports load only when requested, with existing ownership checks.
- Template cards use two columns at desktop workspace widths and one on narrow screens. Technical joins the same grid after Classic and Minimal. Thumbnails on the board are schematic; use actual rendered template previews in the application.
- Template approval has one explicit action after checks pass and sample PDFs have been inspected. Keep the sample selection and PDF inspection accessible, using Short résumé / Detailed résumé / Long entries. Checking and failed states cannot approve. No unexplained fixture checkbox appears.
- Ranking suggestions support direct evidence selection without a separate acceptance gate. Show qualification gaps. Changed evidence/job dependencies require refresh before using stale suggestions. Continue to draft preserves the actual selected evidence.
- Operations distinguish initial load, queued, processing, successful empty, provider failure, and background preview update. Sources remain saved during recovery. Tailor recovery to the actual issue: extraction failure offers another document/manual entry; rejected credentials offer connection management; usage limits explain quota/rate limit; unsupported model or invalid generated content offers choosing another model or trying again. Do not expose internal schema errors as the primary message.
