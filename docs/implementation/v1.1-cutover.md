## Admission gate commands

Run from the repository root. For staging, pause with `pnpm --filter @river/web exec wrangler d1 execute river-staging --remote --env staging --file ../../scripts/sql/v1.1-pause-ai.sql`. For production, use `river-production` and `--env production` in the same command. Never pause an environment until ready to perform its cutover.

Confirm the `river_v11_ai_admission_paused` trigger exists in `sqlite_master`. Query `operations` for Pending/Running rows with input types `job-ai`, `wording-ai`, `source-ai`, `duplicate-ai`, `template-ai` or `source-refinement`. Proceed only when that query is empty. Existing operations may still update their state; new attempts fail atomically at insertion. The old UI may display a generic failure for an attempted AI action during this brief window.

After verifying the deployed BYOK version, resume with the same environment-specific command and `--file ../../scripts/sql/v1.1-resume-ai.sql`. Confirm the trigger is absent before live-provider acceptance. Both files are safe to reapply. If deployment fails, keep admission paused until the intended deployment or rollback is verified. These are temporary operational SQL files, not permanent migrations, and backups restored from the migration bundle do not recreate the pause.

A database backup includes connection ciphertext but cannot decrypt it without the matching encryption secret. Retain each environment's secret for as long as its backups are retained. Do not rotate the encryption secret in place: existing ciphertext would become unreadable. A later rotation needs an explicit re-encryption migration or reconnection procedure.

Rollback keeps the additive tables. Restore the previous deployment only after accounting for newly captured BYOK tasks; do not execute them through the old shared-key implementation. Retain both deployments' history and artifact bytes. A security-incident restore must revoke restored sessions and AI connections before resuming execution.
