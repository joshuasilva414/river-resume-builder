# River v1.2 — composable schemas and simpler résumé workflows

Approved implementation plan from the completed planning interview. The final schema-composition clarification is incorporated below. The user's latest instruction sets the completion target to a complete v1.2 implementation deployed and verified on staging; production deployment is outside this task.

## Summary

Add URL-based job imports, simplify evidence management, introduce composable content schemas and chat-based template editing, and add administrative usage controls.

Schemas can reference other schemas. This defines the required data without forcing users to construct every layer separately. A section can contain direct fields, nested entries, or both.

## Schema composition and template editing

Separate a content schema, which describes data, from a template, which renders data conforming to that schema. Multiple templates can share one schema.

| Schema | Content | User interaction |
| --- | --- | --- |
| Experience section | Heading and a list of Experience Entry records | Add, edit, and reorder positions inline |
| Experience entry | Employer, title, dates, accomplishments | Complete one form |
| Summary section | Summary text | Write directly in the section |
| Skills section | Skill selections | Select from the evidence bank |

- Support typed scalar fields, lists, and references to named schemas. Referenced schemas can describe a single nested record or a list of records.
- A section supplies a default template for its child entries. Users can choose another compatible entry layout without converting the content.
- Schema references describe data shape; they do not require separately creating library records. Text, dates, numbers, and accomplishments are direct values, not mandatory standalone content items.
- Creating an experience entry happens inside its section editor. One save commits the section and any new entries together. A summary requires neither an intermediate block nor a separately created content item.
- Preserve reusable entries and sections. Editing a résumé does not silently change content used elsewhere.
- Use stable field identities to map reusable values across schemas. Preserve unused values when switching templates and request genuinely missing fields. Never silently discard values or invent conversions.
- Define standard education fields, including numeric GPA, institution, and degree. Allow custom fields, entry schemas, and sections.
- Generate forms from schemas. Provide calendar controls supporting year, month/year, full dates, and Present; accomplishment rows with add/remove/reorder controls; and explicit contact fields with labeled links.
- Populate Skills selectors from active Skill evidence. Add Fill from evidence to entry forms: select relevant evidence, fill supported values, leave unknowns empty, and review before saving.
- Replace the primary template editor with chat, a visible starting design, and rendered sample content. Chat can change schemas, references, and LaTeX together.
- Valid chat responses update a working copy and preview. Provide Undo and one Save action. Save validates and retains the complete dependency set; existing saved templates do not change automatically.
- Resolve schema references to specific saved definitions internally. Reject circular references, inaccessible schemas, incompatible child layouts, and unresolved dependencies.
- Permit multi-column layouts within the isolated compiler. Reading-order concerns are diagnostics; unsafe constructs, missing content, and compilation failures remain errors.
- Before adding an entry or section, preview it in the actual résumé at its intended position. Debounce rendering, ignore obsolete responses, and preserve the last successful PDF through failures.

## Imports, evidence, UX, and administration

### Job import

- Provide one Import job action that retrieves a public URL and analyzes its description. Use ordinary retrieval first and Cloudflare browser rendering for JavaScript pages. Review editable results before saving the job and requirements together.
- Browser retrieval capability: https://developers.cloudflare.com/browser-run/quick-actions/content-endpoint/
- Preserve pasted-text input. Provide paste/retry fallback for blocked, login-only, or incomplete pages. Preserve retrieved text if analysis fails.
- Validate public destinations and redirects, bound retrieval size and duration, and treat retrieved content as untrusted.
- Separate Qualifications from Eligibility through the model prompt and output contract. Eligibility is informational, without evidence matching, inferred personal answers, or résumé-creation gates.
- Remove confidence and supporting-passage controls from ordinary views. Retain useful source attribution internally.
- Refresh postings only on request; preserve earlier captures and saved résumés.

### Evidence and bulk actions

- Evidence items contain text, keywords, optional sources, and one of: Skill, Achievement, Experience, Education, Credential, or Other.
- Automatically extract editable evidence after source processing using the selected personal AI connection. Include explicitly named skills throughout the document and avoid silently truncating extraction at the current result limit.
- Use action-oriented résumé phrasing with an implied first-person subject. Omit the person's name and documentary narration. Skill items contain skill names.
- Review extracted items once with Add selected or Add all. Saved evidence is immediately usable. Directly entered evidence needs no source or attestation workflow.
- Remove verification states, claim-review workflows, and required rationales.
- Provide selected/all actions for import results, requirements, evidence matches, and wording alternatives. All covers the complete matching result set across pagination and displays its count.
- Wording assistance presents editable choices with Apply selected and Apply all.
- Keep bulk commands safe to retry. Stale inputs produce a clear refresh path without partially applying an inconsistent batch.
- Remove verification and missing-source export gates. Changed or trashed references are informational. Document integrity failures remain blocking.

### Shared UX and deletion

- Use task language such as Extract evidence, Analyze job, Improve wording, Source, Entry, and Saved versions.
- Remove unnecessary proposal, candidate, draft, provenance, revision, and technical-identifier language from normal workflows.
- Show processing with a spinner, concise status, and Cancel. Select models before execution; cancelled work cannot apply late results.
- Reproduce and fix the Inputs changed warning. Initial paste, accepted results, and unrelated edits must not create false warnings.
- Provide accessible Delete actions for sources, custom templates, evidence, reusable content, sections, and jobs. Delete moves items to recoverable trash without requiring a reason. Preserve content and source material referenced by saved résumés.
- Remove the Appearance settings tab and retain the shared theme control.

### Administration and scoring

- Add an administrator-only dashboard with total and active users, jobs added, imports, evidence additions, saved templates, exports, processing outcomes, and scoring usage.
- Include per-account identity and counts without exposing résumé or source content. Move backup controls into this area.
- Ordinary accounts receive 25 successful scoring results per day, resetting at midnight UTC. Each successful template sample counts separately. Administrators have no daily scoring cap.
- Failed attempts and reuse of retained results do not consume allowance. Reserve capacity atomically before submission, settle once when a valid result is retained, and release unused reservations.
- Show remaining allowance and reset time. Let administrators configure limits and reset individual allowances.
- Remove daily quotas from BYOK processing. Retain bounded concurrency and execution limits.

## Interfaces, migration, and documentation

- Extend shared Effect Schema contracts for composable schema definitions, references, typed values, template bindings, evidence types, URL imports, bulk commands, previews, trash, and administrative usage.
- Update REST and MCP evidence interfaces. Remove verification from advertised commands and permissions; retired verification calls return a clear migration error.
- Version the new schema and rendering contracts. Preserve readers for existing content, template graphs, and saved résumés.
- Adapt existing nested content/block/section records into the new editing experience. Flatten unnecessary wrappers in new content without rewriting historical saved documents.
- Conservatively migrate recognizable structured values. Preserve ambiguous legacy dates and contact text until explicitly edited.
- Make all previously saved evidence usable regardless of its former review state. Preserve text, sources, references, and history. Unaccepted extraction results still require review.
- Default existing evidence without a known type to Other. Keep historical verification records internal and avoid applying the new export policy retroactively to historical exports.
- Update the glossary, specification, build plan, and public guides. Record ADRs for the simplified evidence model and composable schemas with independent layouts.
- Design changed screens and states in Paper before implementation. Preserve River's visual system and track design, implementation, and verification separately.
