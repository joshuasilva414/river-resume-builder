`/admin` requires the authenticated administrator. Its Overview and Accounts tabs return identity and aggregate counts only. Metrics include total users, users with an updated session within 30 days, jobs, source/URL imports, evidence, templates, exports, processing outcomes, and retained scoring results. Each template sample is one result. Counts include retained historical and trashed records. Account search is literal, paginated in sets of 50; aggregate totals remain independent of the search. Existing account ownership checks still apply to content inspectors.

Default allowance, account overrides, and account resets are administrator-only commands with revision or observed-count guards and idempotency receipts. The Appearance tab was removed; the existing shell theme control remains available.

Checkpoint scoring, Save & score, template scoring, and Account settings display remaining allowance, pending reservations, and the next UTC reset. Template scoring explains its sample count before submission. Exhausted accounts can still inspect saved results and export. Allowance refreshes while processing and at the next reset.

## Accounting and migration

Migration `0037_v1_2_usage.sql` replaces the attempt-based daily processing trigger from 0029 with concurrency-only enforcement. It does not edit an applied historical migration. BYOK processing has no daily task quota. Existing limits remain: four active operations per account, sixteen globally, and narrower shared AI/scoring concurrency guards and execution deadlines.

Ordinary accounts default to 25 successful scoring results per UTC day. Administrators are exempt from the daily scoring limit. The global default and account override are stored independently. Historical retained checkpoint results and template samples seed daily usage during migration; active unfinished legacy work receives reservations.

Each result has a stable reservation identity. A checkpoint uses one reservation; a template run reserves each unfinished sample. Reservation and operation creation commit atomically, so competing starts cannot both spend the final slot. Provider submission requires an active reservation. Validated result retention changes Reserved to Consumed in the same D1 batch as saving the result. A database trigger increments the current UTC day's usage only for that transition. Concurrent or repeated retention cannot charge twice.

Terminal success, failure, or cancellation releases any unused reservation. Individual template failures release that sample immediately. Late responses after cancellation, retry, or per-sample failure cannot retain a result against a released reservation. Retry reserves only missing results; recovering retained output does not reserve or consume another result. Invalid provider output and attempts that retain no result consume no allowance. A valid score below a scoring threshold is still a successful provider result and counts once.

Pending reservations survive midnight and count against the current day's available capacity. Completion charges the day on which the valid result is retained. This prevents work admitted before midnight from oversubscribing capacity after reset. Lowering a limit honors already admitted work and blocks new reservations until capacity is available.
