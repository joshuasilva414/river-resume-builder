## Evidence and sources

- A source begins extraction after processing using the selected personal connection/model. Model selection happens before execution. Add a source and manual entry are both available.
- Extracted items have editable type, text, keywords, optional source. Types: Skill, Achievement, Experience, Education, Credential, Other. Skill text is a skill name; other evidence uses action-oriented wording without the person's name or documentary narration.
- One review ends with Add selected or Add all. All includes every matching result across pages, with its explicit total. Show selected and total counts. Saved evidence is usable immediately.
- Manual entry has text, type, keywords, optional source, Cancel, and Save evidence. No verification, rationale, attestation, or intermediate content creation.
- Processing has spinner, short task status and Cancel. Cancellation retains source but does not apply late results. Failure retains source and offers retry/model change/manual entry. Success shows the added count and View evidence.
- Stale batches are atomic: show a refresh action rather than partial acceptance. Retrying a successful bulk action must not create duplicates.
- Source states displayed together on the design board are alternate application states, not simultaneous UI content.

## Jobs, matching, and wording

- One Import job entry switches between Public URL and Paste text. Connection/model are selected before execution. The review retains editable retrieved description, company, title, and categorized requirements. Save job and N requirements saves them together.
- Requirements have select-all/clear selection, editable content/category and delete/add controls. The job import board shows all three illustrative requirements; larger sets use the all-result pagination pattern from evidence.
- Qualifications have evidence matching; Eligibility is informational. Do not infer personal answers or gate résumé creation on eligibility.
- Recovery states include spinner/cancel, blocked or login-only page with Paste description/Try URL again, analysis failure retaining text, cancelled import retaining retrieved text, reviewed refresh, and genuinely stale description inputs.
- Show stale warnings only when inputs relevant to the pending results actually changed. Initial paste, successful acceptance, and unrelated metadata edits do not warn.
- Refresh posting is explicit. Review changes before replacing the current capture; existing saved résumés retain their earlier posting.
- Matching uses Use selected and Use all N matches. Wording choices remain editable and show current wording, proposed wording, and affected entry; Apply selected and Apply all N target the complete result set. Incompatible stale batches offer refresh without partial application.

## Composable editors

- Summary directly stores heading and text; the editor has layout selection and one Save section. No mandatory content item or block step.
- Experience has section heading and a list of Experience Entry forms. Add, edit, reorder and remove positions inline; support selecting saved entries. Save section commits new entries and section together. Keep library edits separate from résumé-local changes.
- A section chooses a default child layout. Each entry may select a compatible layout using the same fields. Preserve unused values on switching and surface genuinely missing required fields.
- Entry fields are generated from schemas. Experience has employer, title, dates, accomplishment rows with add/remove/reorder and Fill from evidence. Education includes numeric GPA, institution, degree and custom fields.
- Date precision supports year, month/year and full-date calendar controls; end date has Present. Preserve ambiguous older text until edited. Contact includes explicit name, email, phone, location and label/URL links; the board details the changed labeled-link pattern.
- Skills selects active Skill evidence. Fill from evidence is on demand: select relevant items, execute using the chosen connection/model, review supported values, leave unknown fields empty, then return values to the unsaved editor. Use these values does not save the section.

## Template chat and previews

- Chat is the primary editor, with visible starting design, selected personal connection/model, a sample selector and real PDF/Extracted text/Checks views. Valid output updates a working copy. Undo restores the previous working copy. One Save template validates and retains all schema/layout dependencies. Older saved templates do not change automatically.
- Fields and entry layouts is an expandable summary. Edit fields opens the schema form; advanced source is secondary. Fields support scalar/list/entry references, custom entry definitions and compatible defaults. Avoid revision IDs or graph machinery in ordinary UI.
- Reject circular references, unavailable entry definitions, incompatible child layouts and unresolved dependencies with actionable messages. Show missing fields without discarding retained values. Unsafe constructs, missing content and compilation failures block save; reading order is diagnostic.
- Template processing uses spinner and Cancel. Failed rendering retains the previous successful PDF and offers retry/Undo; cancellation cannot apply late output.
- Before adding a section or entry, preview it inside the actual résumé at the chosen position, including surrounding content. Select placement and compatible layout, edit if needed, then Add section/entry. This makes a résumé-local copy. A thin blue marker may identify inserted content in the UI and must not enter the rendered document.
- Debounce preview updates and ignore obsolete responses. Pending/failed previews keep the last successful PDF clearly labeled; do not present it as the current version. Retry before adding a version that lacks a successful current preview.

## Administration, trash, and shared states

- Administration is an administrator-only destination. Show total/active users, jobs, imports, evidence additions, saved templates, exports, processing outcomes and scoring usage, with a time window. Per-account identity and counts may expand into further counts; never include résumé/source content.
- Administration contains daily successful-score limit configuration, per-account allowance reset and backup creation/history. Move existing backup controls here from Settings. Admins have no daily scoring cap.
- Normal scoring UI shows remaining/total and 00:00 UTC reset time, plus human relative time where useful. Explain each successful template sample counts separately. Failed attempts and retained-result reuse do not use allowance. Exhausted accounts can still edit/export/view results. Show count corrections only from retained server results.
- Delete actions for sources, evidence, custom templates, reusable content, sections and jobs move to recoverable Trash without a reason. Offer Undo/View Trash after deletion. Trash filters/searches all supported types and has labeled Restore actions. Keep saved résumé content/source references intact; restored items become available for new work.
- Remove the Appearance settings tab. Preserve the shared theme control. Ordinary settings navigation shown here is schematic; keep other existing applicable settings. Administrator navigation is role-gated.
- Use Extract evidence, Analyze job, Improve wording, Source, Entry, Saved versions. Keep internal provenance/revision identifiers out of normal UI.
- Shared processing uses spinner, concise task status, chosen provider/model and Cancel. Cancel cannot apply late results. Personal AI processing has no River daily quota; retain appropriate provider/concurrency/execution errors.
- Changed or trashed references are informational on export. No verification/source acknowledgment gates. Missing content, unsafe rendering and document integrity failures still block the current export, with an affected-entry recovery action.
