# River v1.2 public guides

The 21 public guides under `apps/web/src/components/docs/pages/` now describe the approved v1.2 workflows. They are release documentation, not evidence of browser or hosted acceptance. The release owner records that acceptance separately.

## Updated guidance

- The practice tutorial builds direct Summary and nested Experience content using fictional facts. Manual evidence and pasted job intake work without an AI connection.
- Source intake describes automatic evidence extraction with the selected personal model, editable results, one Add selected or Add all action, complete counts across pages, cancellation, and recovery.
- Evidence uses six types, text, keywords, and optional sources. Historical verification decisions remain readable but no longer gate ordinary use or export.
- Job intake describes public URL retrieval, browser fallback, editable details and requirements, retained text after analysis failure, pasted/manual recovery, cancellation, and explicit reviewed posting refreshes.
- Qualifications guide evidence matching. Eligibility remains informational, without inferred personal answers or résumé gates.
- Selected/all requirements, matches, and wording cover the complete set and describe stale-batch refusal and idempotent retries. Wording choices can be edited before application.
- Library and content reference guides explain direct values, named schemas, inline nested entries, one section save, date precision, numeric GPA, labeled contact links, active Skill evidence, Fill from evidence, compatible layouts, and retained unused values.
- Template guidance covers a visible starting sample, chat edits to a working copy, Undo, one Save, complete reference validation, and diagnostic reading-order findings.
- Editing includes previews in the actual résumé before insertion, previous-preview retention, and protection against late responses.
- Export guidance removes source and verification acknowledgment requirements. Document integrity and compilation failures still block output. Earlier export reports remain historical records.
- History and troubleshooting describe recoverable Trash, explicit library updates, immutable saved documents, and migration from earlier content/block and review terminology.
- Account and workspace reference guides distinguish personal AI with no daily River quota from the default 25 successful scoring results per UTC day. Each successful template sample counts, administrators are exempt, failed or cancelled work releases capacity, and retained-result reuse does not charge.
- The administrator reference describes aggregate and per-account identities/counts, scoring controls, and backups without suggesting access to private user content. Theme guidance uses the shared control.

## Compatibility and checks

Renamed titles flow through the existing guide registry and navigation. All 44 internal guide links resolve to existing guide slugs.

`pnpm exec biome check apps/web/src/components/docs` passed for 23 files. The compatibility/link audit compared each page with its `HEAD` version. No full build, browser inspection, live-provider test, or deployment was run for this documentation work.

## Integration follow-up

The integrated guide labels were checked against the implemented workflows during local and hosted acceptance. One template Save validates and approves, insertion uses a current contextual preview, Administration contains scoring controls/backups, and Settings no longer describes a shared daily BYOK processing allowance. Exact evidence modes and outcomes are recorded in [hosted acceptance](v1.2-hosted-acceptance.md) and the [Paper handoff](v1.2-paper.md).

Fill from evidence currently previews supported values before Use these values. The guide tells users to apply those reviewed values and finish editing in the entry form; it does not promise an editable form within the preview. The implementation fills selected accomplishments, Skill values, and explicitly labeled text while leaving unknown values empty and existing unspecified values intact.

The final-document refinement guide retains its existing candidate review and separate saved-version behavior. Reusing a layout is documented through Templates; the guide does not promise that the older Promote a layout idea action automatically updates the new schema/chat working copy.

Structured-content wording assistance was implemented after the guide pass. Direct Summary and nested text-list fields use the same selected/all transaction, stale guards, cancellation, and Undo as legacy wording targets. Domain and focused Workers tests cover the complete-set and mixed-target behavior. Hosted wording generation, editing before acceptance, saved-version rendering and PDF export passed; the evidence record distinguishes the representative live batch from automated cross-page and atomicity checks.
