# River v1.2 recoverable Trash

Design: [Paper handoff](v1.2-paper.md), artboard `C25-0`. Implemented with the existing River shell, tokens, and accessible controls. Browser acceptance is recorded by the integration task separately.

## Behavior

- `/trash` provides an owner-isolated, searchable and type-filtered view of deleted Sources, Evidence, Jobs, reusable Content, Entries, Sections, and custom Templates. The server counts the complete matching set and returns pages of 50 items.
- Restore clears the deletion state on the retained record. It does not recreate files, evidence material, library revision graphs, job snapshots, or template graphs.
- A workspace-level notification offers Undo after deletion or restoration, including when the original row or inspector disappears. Undo uses the returned revision and a stable command key. A concurrent edit produces a conflict rather than overwriting the newer record.
- Source, evidence, job, and library lifecycle actions use their existing atomic commands, receipts, and audit history. Library deletion no longer requires a reason. New shared Trash mutations are owner-only; administrators do not gain cross-account content access.
- Migration `0038_v1_2_trash.sql` adds `template_designs.archived_at` and indexes the Trash lookup. It leaves every template revision's validation/approval lifecycle unchanged. A deleted Approved template remains renderable for saved references. It is hidden from active template lists and unavailable as a new editing/donor base until restored.
- No permanent deletion or source-file cleanup is performed. Existing saved résumés retain their content and source material.
- Workspace navigation includes Trash for every account and Administration only for administrators. The existing shared theme control remains.

## Integration

`TrashAction` in `apps/web/src/components/trash/actions.tsx` accepts an item with `id`, `kind`, `label`, `revision`, and `archivedAt`. It handles Delete/Restore, query refresh, and the workspace notification. `useTrashFeedback` lets existing lifecycle commands publish the same notification using their returned revision.

Custom template list results now include `designRevision` and `archivedAt`. Use the design revision for Delete/Restore; review revisions belong to validation and approval.
